## ZCode 对照与适配决定

重新阅读了 ZCode 的 `toolDiffPreview.ts`、模型轨迹、Git 工作区状态、设置写入队列、任务工具记忆，以及 `pluginUiInteractions.ts` 和对话框队列。路径和固定版本记录在 `vendor/zcode/ATTRIBUTION.md`。

- diff 沿用唯一行锚点和 LIS 的思路，补上矩阵、总体计算量、输入及 DOM 预算。
- 轨迹沿用结构和有界尾读，另用异步串行写入、严格字节预算及显式记录开关。正文可能含用户主动输入的敏感信息，不能宣称全文本永不含秘密。
- Widget 沿用可信宿主交互、异步确认后重检会话绑定的边界。VCPChat 采用每条可见宿主确认，适应其消息组件桥。
- 笔记和状态操作显式捕获身份，保存队列及迟到结果不能覆盖新编辑器或工作区。
- 全局工具状态与会话子聊归属分开，跨话题不会因不存在侧聊而折叠正在使用的 Git 标签。

## 拆分过程的额外修复

逐层完整门禁还暴露了集成 tip 看不到的两个依赖问题：侧聊按钮原先在第 1 层指向第 2 层才存在的容器，现将按钮与容器一起放在第 2 层；第 7–9 层的过渡状态样式改为与最终状态面板一致的匹配对象作用域、token 和响应字号。

最终边界复核另补三组反例：ASAR 内的 Python 确认脚本必须由外部解释器读到真实文件；轨迹清空标记不受内容保留期限删除，恢复清理跳过正在写入的原子临时文件；同一工具并发请求不能仅凭结果条数相等推断成功路径。对应修复归入第 6、11、9 层。

consumer 扫描此前会把工作目录里的 HTML 探针、嵌套 checkout 和输出文件纳入产品清单，造成生成物随本机环境变化。现在排除 work/outputs，新增实际 collector 回归，保留普通 modules/workspace 子目录的扫描；每层清单在不同检查目录重新生成后与提交一致。

仍需明确的产品取舍：

- 命令记录没有 topicId，界面标为“命令（文本关联）”。仅去掉首尾空白；引号、换行和内部空白保留。相同文本仍可能来自其他话题。
- `completed` 表示结束，退出码未知时显示中性状态，不冒充执行成功。
- 原生 `node-pty` 的 Windows 清理辅助进程偶尔打印 `AttachConsole failed`；上述输入、退出、重启断言通过，日志仍保留。未修改第三方包来隐藏这条日志。
- 管理员确认需要机器上可用的 Pythonw/Tk；验证脚本物理可读、缺失拒绝与清理，没有触发实际 UAC 或 Tk 确认窗口。
- 验证了 Windows unpacked 产物及其模块，没有验证签名后的 NSIS 安装/升级，也未完成 macOS/Linux、实际 VCP 服务器群聊模型请求、完整语音和长期性能 soak。
- 本次不验证原件中的“7s→4s”等历史性能陈述，也不以单元测试替代整应用视觉验收。
